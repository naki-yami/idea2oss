# 领域文档布局

> setup 一次性配置的产物之三 ｜ 模式：**单上下文**

## 四处落点，各管一件事

| 文件 | 管什么 | 不管什么 |
|---|---|---|
| `CONTEXT.md`（根目录） | **术语表**：本仓库的黑话一句话定义 | 不是规格；不放决议 |
| `docs/decisions.md` | **决议台账**：谈定一条追加一行，编号不复用 | 不放术语；不放讨论过程 |
| `docs/adr/NNNN-*.md` | **架构决策全文**：难逆转 + 脱离上下文会费解 + 真实权衡，三条同时满足才写 | 多数决议不够格，进台账即可 |
| `docs/architecture.md` | **模块与接缝清单**：每个接缝一行（名字 / 通过它的是什么 / 谁调用） | 不写实现细节 |

## 三条界限（容易踩）

1. **`CONTEXT.md` 只是词汇表。** 它不承载需求，也不承载决策；把它当规格用，是这套流程里最常见的一次性错误。
2. **多数决议不够格写 ADR。** 够格的门槛是三条同时满足：难逆转、脱离上下文会费解、有真实权衡。一次会话一条 ADR 都不产生是正常的——这时在仓库里明写「本步无 ADR」，而不是让它空着让人猜。
3. **规格是快照。** `.scratch/<feature>/spec.md` 会过期、不回头改；学到的新东西写进 `CONTEXT.md` 或 `docs/adr/`。

