# triage 标签

> setup 一次性配置的产物之二 ｜ 每个标签名等于它的角色名

| 标签 | 含义 | 本仓库怎么用 |
|---|---|---|
| needs-triage | 待维护者评估 | 新 issue 的默认落点 |
| needs-info | 等报告者补信息 | 报告里没有复现步骤 / 版本 / 环境时 |
| ready-for-agent | 规格完整，可交给无人值守的智能体 | **本仓库谨慎使用**：只打在票据上，不打在 spec 上 |
| ready-for-human | 需要人工实现 | 涉及许可证、法务、对外承诺的，一律这个是 |
| wontfix | 不处理 | 与「不做什么」冲突的请求，关掉时写明理由 |

## 映射冲突

平台上的标签还是 GitHub 默认那套（`bug` / `enhancement` / `wontfix` …），本仓库上面这五个名字**没有在平台上建**。要用就自己建，建之前先对一遍默认集：`wontfix` 两边都有且含义一致，可以直接用；另外四个是本项目自定义的，直接用不会撞车。带冒号的写法（`bug:triage`）平台建不出来，要映射就改在 `docs/agents/issue-tracker.md` 里，否则 triage 会重复创建标签。

## 一条已知坑（与本集技能直接相关）

`to-spec` 这类技能产出的文档会被打上 `ready-for-agent`，而按标签轮询的无人值守代理可能**整份实现**它，而不是捡票据切片。所以：

- 拆票跑完后，**手工把 spec 上的标签摘掉**（这一步没有自动化，写进票据的收尾动作）；
- 或者在代理提示词里明确排除父级文档。

## 本地模式下的替代

本地 markdown 模式没有标签系统，用票据头的 `Status:` 承担同样的角色：`todo` / `doing` / `review` / `done`。**做完的票手工改成 `done` 并写上验证指针**——不要让 frontier 自己变干净（已知缺陷：流水线尾部会敞开，票据永远停在 `ready-for-agent`）。
