# 立项 brief —— idea2oss

> 第 0 步 · 产出物：`brief.md`（一页以内）｜ 判据：五句话都写得出，「不做什么」≥1 条、「放弃条件」≥1 条，最小可验证切片一句话说清
> 本步 10 分钟、一个人做、不开代理。

## 五句话

1. **给谁用**：已经在用 AI 智能体写代码、并且打算把成果交给别人用（同事接手、开源、发版）的独立开发者与小团队。不是「所有开发者」——只写代码不出手的人不需要这套。

2. **解决什么**：他们现在让代理一路写下去，中途不落盘、不设判据，最后交付时说不清「做完了没有」，接手者也看不懂为什么这么写。痛在**第 5 步返工**和**交付当天**。

3. **成功长什么样**：一个没读过本仓库的人，在干净环境里按 README 装上技能，**30 分钟内走完一次 L0 全程**（立项一句话 → 首次提交 → 一张票做完 → 自己跑一遍写出 `Accept:`），并且第二天愿意再用一次。

4. **不做什么**：
   - 不自己做运行时、不做 GUI、不做 Web 服务；
   - 不做代码脚手架（生成项目骨架是 `scaffold_project.py` 的事，不在本集内）；
   - 不绑任何外部技能集：任何技能都必须能被单独拿走使用；
   - 不替人做决定：技术栈、许可证、法务判断、对外承诺一律不代劳。

5. **什么条件下放弃**：三个月内，九步判据没有被任何真实项目完整用满 3 次（以台账里的 `D-nn` 与票据 `Covers:` 为证），停止维护，README 顶部写明归档与替代品。

## 最小可验证切片

**一张命令：`python tools/check_project.py --dir . --quiet` 在空项目上给出可执行的缺失清单。**
它验证的核心假设是：结构判据可以被机械检查——如果这条都不成立，后面所有「判据」都只是纸面话术。

## 许可证

- 开不开源：开源。
- 选定：**MIT**。
- 理由三条：① 想被最广泛使用，包括用在闭源产品里；② 本项目没有专利风险敞口，不需要 Apache-2.0 的显式专利授权；③ 技能要能被人随手拷进自己的工作流，任何传染性许可都会挡掉一半使用者。
- 落地三处（第 8 步复核）：仓库根目录 `LICENSE` 全文、`pyproject.toml` 的 `license` 字段、README 许可段落——必须一致。
