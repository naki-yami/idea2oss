# 流程体检与度量（只看趋势，不打分）

> 对应手册第 14 章 ｜ 产出物：六个指标的趋势记录 + 一条「该改哪一步」的结论 ｜ 完成判据：六个指标都有可复查的痕迹（命令 / 编号 / 分钟数），且有一份改了流程之前的基线

## 何时用 / 何时不用

**用**：想知道这套流程有没有用；连续两周趋势变差；评审返工或逃逸缺陷偏高；**准备改流程之前**（先测基线）；交付一批票之后复盘。

**不用**：
- 拿它给人打分、排名。指标的意义是让你知道该改哪一步，不是给你打分。
- 单张票还没做完就问「流程好不好」——样本太小，先做完再看。
- 半天内、只你自己用的 L0 活：判据够用就行，不必上度量。

**采集方式就是票据头那几行**（`Verify:` / `Rounds:` / `Sessions:` / `Review:` / `Accept:`），加上第 6 步写进票据的验收结论、以及台账里的编号。**写票的时候顺手填，不额外记账。**

## 输入（开工前必须到手的）

1. 票据文件（头部六行 + Comments）：`templates/ticket.md`——`Rounds:` 与 `Sessions:` 是前两项指标的取数来源。
2. 台账（编号 + 证据栏）——决议追溯率的分母（→ 调用 `decision-ledger`）。
3. 第 6 步的验收结论（`Accept:` 行）与两轴发现项计数（`Review:` 行）。
4. **上一个周期的同一张表**。没有就先采两周——这两周的数据就是基线，本身就是产出物。
5. 发布后修的 bug 清单与已交付票数（逃逸缺陷用）。
6. 一个干净环境 + README（陌生人上手时间用）。

## 动作

1. **先测基线，别急着改流程。** DORA 2025 的结论是：AI 是「放大器」，它放大团队既有的强项，也放大既有的弱项。没有基线，你既不知道流程带来的是改善，也不知道它放大的是哪一面。做法很土：用当前这套指标先记两周，再动流程。
2. **采六个指标**，全部来自已有文件：

   | 指标 | 怎么采 | 希望的趋势 | 异常说明什么 |
   |---|---|---|---|
   | 一次收敛率 | 票据头 `Rounds:` 为 1 的比例 | 上升 | 偏低说明票切得太大，或需求没说清 |
   | 决议追溯率 | 台账中能在实现与验收里找到证据的决议比例 | 升到 100% | 低于 100% 说明决议在这条流水线上被漏掉或被压弱了 |
   | 评审返工 | 每票 `Review:` 的发现项计数 | 下降 | 偏高说明跳过了第 2 步，或接缝没定 |
   | 逃逸缺陷 | 发布后修的 bug 数 ÷ 已交付票数 | 下降 | 偏高说明第 6 步的验收是走过场 |
   | 上下文成本 | 票据头 `Sessions:`，以及是否用了交接 | 稳定在 1 | 上升说明单票太大，或纪律松了 |
   | 陌生人上手时间 | 干净环境按 README 到跑通的分钟数 | 降到 30 分钟以内 | 超过 30 分钟说明第 8 步没做完 |

3. **每个数字都留可复查的痕迹**：一条命令、一个编号、一个分钟数。**不要写「感觉快了」。** 依据见「动作」第 5 条的第一条硬规则。
4. **用上下文预算这把尺子判票据尺寸**：smart zone 的量级约 150k token；业界给过一条估法——一张票约 100k token。合起来两条实用判断：
   - 明显撑不满一次会话的票，可以合并；
   - **需要跨两个会话的票就该切开，而不是靠压缩硬撑**——压缩是收敛信息，而这里丢掉的正是决议的精度。
   - 顺带：处理顺序是「继续当前会话 → 清空 → 交接 → 派子代理 → 压缩」，需要交接时 → 调用 `session-handoff`。
5. **三条硬规则**（都有外部证据，不是你的偏好）：
   - **不要采信自报数据。** METR 做过一次随机对照试验：16 名资深开源开发者、246 个真实任务，允许使用 AI 的那一组完成速度反而慢 19%；而同一批人在开始前预计快 24%，做完之后仍然认为自己快了约 20%。**主观感受与实测可以反号**——所以六个指标全部要求留下可复查的痕迹，不许用「感觉快了」当数据。
   - **先测基线，再谈提升。** 见第 1 步。
   - **不要用一个指标统治一切。** DORA 现行的交付性能指标是五项：部署频率、变更前置时间、变更失败率、失败部署恢复时间、部署返工率（早期「四键」里的 MTTR 已被「失败部署恢复时间」取代）。它明确把「只看一个指标」列为陷阱：单看速度会牺牲稳定性，单看稳定性会牺牲交付。这六个指标同理——**看组合，不看某一个**。
6. **只看自己项目的趋势**，不做跨项目横比：两个项目的票大小、语言、依赖都不一样，横比出来的差异大部分不是流程造成的。
7. **连续两周趋势变差 → 回头改流程**，通常是先回第 2 步和第 4 步（需求与切票），而不是更努力地写代码。
8. **写下结论**：哪几个指标变了 / 指向哪一步 / 下一周期改什么 / 改完复测哪几个指标。

## 产出物

- 六个指标的周期记录（一张表），每条数字带可复查痕迹。
- **一条结论**：该改九步里的哪一步，以及下一周期改什么。
- 改流程前后的两份记录（用于对比；第一份就是基线）。
- 凡是 `Sessions:` > 1 的票，每张一行处置：合并 / 切开 / 留观。

## 完成判据

- [ ] 六个指标都采到了数；采不到的写明「不适用 + 为什么」，不留空。
- [ ] 每个数字都能指到一条命令、一个编号或一个分钟数——表里没有「感觉快了」这类描述。
- [ ] 至少有一份两周以上的基线记录（第一次做时，基线就是本次产出物）。
- [ ] 结论指向了九步里**具体的一步**，不是「以后更认真点」。
- [ ] 结论建立在至少三个指标的组合上，没有任何一个指标单独下了结论。
- [ ] `Rounds:` / `Sessions:` / `Review:` 三行是写票时当场填的；事后追溯填的已标注并被排除出统计（凭记忆的数字正是第一条硬规则要挡的东西）。
- [ ] 每张 `Sessions:` > 1 的票都有处置结论。
- [ ] 改过流程的话：复测过同一批指标，且两份记录放在一起可对比。

## 手工兜底

- **没有 tracker**：票据就是本地 markdown（`.scratch/<feature>/issues/NN-*.md`），头部六行照写，照样能采。
- **票据头没填、也补不出来**：把这张票**排除出统计**，并在记录里写明样本量——不要凭记忆编数字。
- **没有 CI / 没有发布流程**：逃逸缺陷用「修 bug 的次数 ÷ 交付的票数」近似，并在记录里注明口径变更。
- **没有第二个人**：陌生人上手时间自己掐——清空虚拟环境（或换一台机器 / 新目录），只读 README 从零跑一遍，记分钟数。找不到干净环境就记「无法测」，不要猜。
- **没有两轴评审技能**：用 `templates/manual-review.md` 手工过一遍，`Review:` 计数照填——如果装了 code-review 或类似技能就用它；没有就按手工清单走。
- **解析不了 token 数**：`Sessions:` 与 `Rounds:` 就是你的代理指标，不必去数 token。

## 下一步

→ 按结论回到对应的一步：需求或验收说不清 → 调用 `grill-with-ledger`；票据切法有问题 → 调用 `ticket-plan`；验收走过场、逃逸缺陷高 → 调用 `dual-axis-review`；单票跨会话 → 调用 `session-handoff`；陌生人上手时间降不下来 → 调用 `oss-launch`；该剪裁档位 → 调用 `project-brief`。

## 反模式

| 反模式 | 为什么错 | 改成 |
|---|---|---|
| 用「感觉快了」当数据 | METR：允许用 AI 的一组实测慢 19%，同一批人事前预计快 24%、事后仍认为快约 20%，主观与实测可以反号 | 只认命令、编号、分钟数 |
| 没测基线就改流程 | 不知道改善了什么，也不知道放大器放大的是哪一面 | 先用这套指标记两周，再动流程 |
| 用一个指标统治一切 | 单看速度牺牲稳定性，单看稳定性牺牲交付（DORA 现行五项，单指标是陷阱） | 看组合，至少三个指标一起读 |
| 跳过第 2 步直接实现 | 需求在实现中途才暴露，返工加倍——一次收敛率与评审返工同时恶化 | L1 / L2 先拷问，再拆票 |
| 在一个会话里做完两张票 | 第二张票背着第一张的试错预算，`Sessions:` 悄悄涨上去 | 一票一会话，票据头当场填 `Sessions:` |
| 用「再试一次」代替「回上一层」 | 上下文耗尽不会带来收敛，只会更贵更乱 | 两次不收敛就重切票 / 补需求 / 做原型 |
| 发现项标成「稍后处理」但不建票 | 欠账会被忘记，评审返工的数字也失去意义 | 当场开票，或写进 ADR 明确接受 |
| 让代理验收自己写的代码 | 自己判自己等于没验收，逃逸缺陷随后上升 | 技术验收用两轴评审，产品验收你亲手跑 |
| 无人值守跑多个代理，不看代理数与 token | 已知会递归，实测能烧掉数十万 token，上下文成本直接爆 | 限定代理数与预算，事后检查后台任务列表 |
| 仓库里没有任何人能看懂的说明 | 陌生人上手时间永远降不到 30 分钟，项目只有你自己能用 | 补齐第 8 步的门面，用陌生人 30 分钟测试验收 |
