# 交付与会话交接

> 对应手册第 7 步（含第 12 章纪律）｜ 产出物：提交前检查 + PR 正文 + 交接文档 ｜ 完成判据：检查跑过一次、PR 回答了四个问题、交接文档只给路径且已脱敏

## 何时用 / 何时不用

**用**：一张票验收通过、准备提交或推分支；要开 PR；出现"该交接了"的信号（见动作第 6 步）；一轮做完要开始第二轮。

**不用**：票还没验收（回 `dual-axis-review`）；只是中间过程的日常提交（不需要 PR 正文，但提交前检查照跑）；一次性的本地实验（不进主干就不必写交接文档）。

**三件事，一件都不能省**：把检查前移到提交前、准备 PR、把会话交接出去。前两件是对别人负责，第三件是对下一个会话负责。

## 输入（开工前必须到手的）

1. 已验收的票据，含 `Verify:`（一条能跑的命令）与 `Accept:`（你本人写下的结论）两行。
2. 当前分支与要交付的改动（`git status`、`git diff`——你要知道每一处改动属于这张票）。
3. 这个项目的检查命令：lint / typecheck / test 分别是什么。
4. 相关路径清单：spec、票据、ADR、台账、架构文档的位置（交接文档只抄路径，不抄内容）。
5. 存放交接文档的系统临时目录路径（Linux/macOS `$TMPDIR` 或 `/tmp`；Windows `%TEMP%`）。

## 动作

1. **把检查前移到提交前**——三选一，按项目实际情况挑
   - **Node 项目**：装一套提交前钩子——Husky 的 `pre-commit` + lint-staged 对暂存文件跑格式化 + 在 `pre-commit` 里跑 typecheck 和 test。装完它会把你**当前所有改动一次性 stage 并提交一次**当作冒烟测试，所以只在干净的项目目录里做，别在文件庞杂的目录里跑。
   - **不是 Node 项目**：跳过钩子，把同样的检查放进 CI，或写一份提交前自查清单（lint / typecheck / test 三条命令），贴在 `CONTRIBUTING.md` 或 `AGENTS.md` 里。
   - **不装任何工具**：提交前手工跑一遍这三条命令，并把命令写进文档，让下一个人照跑。
   - 完成：钩子或清单**存在**，并且**成功跑过一次**（不是"装好了但没跑"）。

2. **写 PR 正文——回答四个问题**（结构抄 `templates/pr.md`，不要改结构）

   | 问题 | 写到什么程度 |
   |---|---|
   | 改了什么 | 一段话，不是 diff 的抄写 |
   | 为什么 | 关联的票据 / issue 链接；解决什么问题；不做会怎样 |
   | 怎么验证 | 命令、步骤、预期结果；必要时贴输出片段 |
   | 风险与回滚 | 最坏情况；影响范围；出问题怎么退回去 |

   - **缺最后一条的 PR，在出问题时没人敢合并。**
   - `Closes #NN` 写在「关联」段；一票一 PR，或一票一分支。
   - 边界说明：本技能不管 Git 操作本身——提交、打 tag、推远端都是你自己的事。

3. **写交接文档**（结构抄 `templates/handoff.md`，六段，结构不要改）
   1. **当前状态**：现在在哪一步 / 哪张票做到一半。
   2. **已完成**：**只列结果，不列过程**（过程在 diff 和票据里）。
   3. **未完成与下一步**：下一个会话的第一件事，**明确到文件和函数**。
   4. **关键路径**：**只给路径，不抄内容**——规格 `.scratch/<feature>/spec.md`、票据 `.scratch/<feature>/issues/NN-*.md`、决策 `docs/adr/NNNN-*.md`、台账 `docs/decisions.md`。
   5. **suggested skills**：下一个智能体按顺序该调用哪些技能；技能缺失就写对应的手工兜底路径。
   6. **已知坑**：踩过的坑与结论；没有就写"无"。

4. **把交接文档存到操作系统的临时目录**
   - 不是当前工作区，不进仓库，不提交。它在 `git status` 里出现就是放错了。
   - 理由：交接文档是最容易被随手贴进别处的东西——放进仓库等于永久留下，还会和文档分叉。

5. **自己复核一遍脱敏，再依赖它**
   - 扫 API key、token、密码、cookie、连接串、私钥、个人信息（姓名、邮箱、手机号、客户数据），全部换成 `<REDACTED>`。
   - 复核命令示例：`Select-String -Path <文件> -Pattern 'api[_-]?key|token|secret|password|PRIVATE KEY'`（macOS/Linux 用 `grep -niE '<同样的模式>' <文件>`）。
   - **别只依赖"技能说它会脱敏"。** 脱敏失败属于"平时看不出来、出事时无法挽回"的缺陷，写完之后自己从头读一遍再交出去。

6. **判断：该交接，还是硬撑**（出现任一条就是交接信号）
   - 你在重复解释同一件事（通常是第二遍）。
   - 要读的文件比要回忆的对话多。
   - 票据的验收判据变了——说明这张票已经不是原来那张票。
   - 出现任一条就交接，或者直接开新会话。硬撑到上下文耗尽，最后一样要交接，只是交接得更差。

7. **二次开发按独立纪律走**
   - 进入第二轮**不要在原会话里接着聊**：把它当成一个全新的小周期，重走"需求对齐 → 拆票 → 实现"（→ 调用 `project-brief` / `grill-with-ledger` → `ticket-plan` → `build-ticket`）。
   - 第一轮结束时的上下文里装满了已经过期的假设——它们不会再帮你，只会替你做决定。

8. **名字澄清（一句话，写进交接文档就够）**
   - 网上流传的 `/spawn` 不存在；spawn 只是这套技能正文里的英文动词（"spawn sub-agents"）。**交接技能只写文档，不启动任何进程。**
   - 另有一个会派后台代理接手的版本（claude-handoff），只支持 Claude 且要调 `claude --bg`；没装 Claude CLI 的环境用不了，不必为它改流程。

## 产出物

- 提交前钩子，或一份提交前自查清单（二选一，存在且跑过一次）。
- PR 正文（四问齐全，结构同 `templates/pr.md`）。
- 交接文档一份（`templates/handoff.md` 六段，存在系统临时目录，已脱敏）。
- 下一张票的输入清单：读哪几个文件、跑哪条命令。

## 完成判据

- [ ] 提交前钩子装好并成功跑过一次；或（非 Node / 装不上）同款检查已进 CI，或提交前自查清单已写进文档。
- [ ] PR 正文四个问题都有答案，`风险与回滚` 一栏非空，也不是"无风险"三个字。
- [ ] PR 里有关联票据（`Closes #NN` 或等价的链接）。
- [ ] 交接文档六段齐全；`关键路径` 段里全是路径，没有粘贴任何正文内容。
- [ ] 交接文档在我操作系统的临时目录里，且没有出现在 `git status` 的改动里。
- [ ] 我本人把交接文档重读了一遍，搜不到真实密钥与个人信息（附上那次搜索的结果）。
- [ ] `未完成与下一步` 明确到文件和函数，下一个会话读完能直接动手。
- [ ] 下一张票的输入清单已写清（读哪些文件、跑哪条命令、验收判据是什么）。

## 手工兜底

- **如果装了 `handoff` / `pr` / `setup-pre-commit` 这类外部技能，就用它们；没有就全手工**：PR 正文抄 `templates/pr.md`；交接文档抄 `templates/handoff.md`。
- **没有脱敏工具**：自己逐段读一遍，把 `api_key`、`token`、`password`、私钥、真实姓名/邮箱/手机号换成 `<REDACTED>`。这一步不能跳过，也不能外包。
- **装不上提交前钩子**：把 lint / typecheck / test 三条命令放进 CI，或写一份提交前自查清单——别因为工具缺失就跳过检查。
- **临时目录不可写**（受限环境/沙箱）：写到工作区之外任意不会被提交的位置，在文档第一行注明"不要提交"，并确认 `.gitignore` 覆盖它。
- **下一个会话还是你自己**：文档照写。写下来才算落盘，记忆不是文件，对话不是文件。
- **没有平台可开 PR**（纯本地仓库）：PR 正文改写成一段交付说明放进票据或提交信息里，四个问题一个都不能少。

## 下一步

→ 要对外开放的仓库 → 调用 `oss-launch`；票还没验收 → 回 `dual-axis-review`；开始下一个周期 → 调用 `project-brief`。

## 反模式

| 反模式 | 为什么错 | 改成 |
|---|---|---|
| PR 缺"风险与回滚" | 出问题时没人敢合并，也没人知道怎么退回去 | 写最坏情况 + 回滚步骤 |
| 交接文档里抄规格、抄计划 | 两份内容立刻分叉，下一轮读的是过期副本 | 只给路径，内容在文件里 |
| 交接文档放进仓库 | 会被提交，还最容易被随手贴到别处 | 系统临时目录 + 不提交 |
| 依赖工具自动脱敏，自己不看 | 脱敏失败平时看不出来、出事无法挽回 | 写完自己重读一遍并搜索一遍 |
| 等上下文耗尽才交接 | 交接质量随剩余上下文一起下降 | 出现任一信号就交接 |
| 第二轮在原会话接着聊 | 过期的假设替你做决定，把第一轮的试错背进来 | 当新周期重走需求 → 拆票 → 实现 |
| 在文件庞杂的目录里装提交前钩子 | 它会把所有改动一次性 stage 进去 | 只在干净的项目目录里做 |
| 交接文档只写"继续做 X" | 下一个会话还得重新问一遍 | 明确到文件和函数 + 输入清单 |
