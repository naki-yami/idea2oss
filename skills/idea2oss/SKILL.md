# idea2oss 总入口（九步法路由）

> 对应手册 TL;DR、第十二章、第十三章 ｜ 产出物：一句档位判断 + 一行「当前第几步 / 下一个技能」 ｜ 完成判据：档位判出来了，当前步与下一技能都指得出，跳过的步都写明了凭什么跳

## 何时用 / 何时不用

**用**：任何一次会话的开头；用户说「我想做个东西」「这活该走几步」「下一步干什么」「现在该用哪个技能」；每次要升级或降级档位；要把流程交给别人（或另一个代理）执行时。

**不用**：已经确定在第 N 步、也知道该调哪个技能——直接调那个技能，别绕门口。单个技能的内部细节不写在这里（每个技能自己写）。

**一句判据**：技能可以换，判据不能省。九步都能手工走完；没有判据，走完也没人知道做没做对。

## 输入（开工前必须到手的）

1. 用户这一句诉求的原文（「我想做个东西」也算输入）。
2. 目标目录的现状：是不是 git 仓库、有没有 `AGENTS.md`、有没有 `.scratch/`、有没有 `docs/adr/`。
3. 这活的三个属性：只你自己用还是要给别人用；要不要开源；碰不碰用户数据或密钥。
4. 已经走到哪一步：现在手上有哪些文件（brief / spec / 票据 / 台账）。

## 动作

1. **先判档位**（对号入座，不要凭感觉）：

   | 档 | 什么情况 | 走哪几步 | 不能省的 |
   |---|---|---|---|
   | L0 一次性 | 半天内做完、只你自己用、不进主干 | 0（一句话）→ 5 → 6（自查一遍） | git 卫生；密钥与数据边界 |
   | L1 常规功能 | 1–3 天、一次会话装得下、影响自己或小团队 | 0 → 1 → 2 → 5 → 6 → 7 | 第 2 步拷问（否则第 5 步会返工）；第 6 步检测 |
   | L2 正式工程 | 一次会话装不下 / 要给别人用 / 要开源 / 多人协作 / 碰用户数据 | 全九步 0–8 | 判据、体检指标、第 8 步 |

2. **对照升级判据**——满足任一条，直接跳到 L2：
   - 有第二个人要用你的代码，或者你打算开源；
   - 要发版、要有版本号；
   - 有第二个贡献者（哪怕只是同事帮忙看）；
   - 处理用户数据、凭证、金钱，或者对接第三方服务。

3. **对照降级判据**——连续两张票都一次做完、零返工，可以把该档「必须」的文档降成随手记。**判据不能省**，它是这条流程里唯一不能省的东西。

4. **定位当前步**（九步地图，判据一栏照抄，不要自己改写成形容词）：

   | 步 | 做什么 | 产出物 | 完成判据（一句话） | 技能 |
   |---|---|---|---|---|
   | 0 | 立项 | `brief.md` | 五句话写得出来：给谁、解决什么、成功长什么样、不做什么、什么条件下放弃 | `project-brief` |
   | 1 | 初始化本地 git 仓库 | `.git/` + `.gitignore` + 首次提交 | 首次提交在，`git status` 干净，历史里没有密钥 | `repo-bootstrap` |
   | — | 每仓库一次的环境配置 | `docs/agents/` 三份 + `AGENTS.md` 的「## Agent skills」 | tracker、triage 标签、领域文档布局都有落点；技能集版本已锁 | `repo-setup` |
   | 2 | 拷问 | `CONTEXT.md` + 决议台账 + 可能的 ADR | 术语表非空；台账每条决议可验证；该类决策有 ADR 或写明「本步无 ADR」 | `grill-with-ledger`（纪律 `decision-ledger`） |
   | 3 | 产品设计文档 | `.scratch/<feature>/spec.md` | 七段齐全，「范围之外」非空，每句能指回你说过的话 | `write-spec` |
   | 4 | 技术方案与开发计划 | 接缝清单 + 票据图 | 接缝与成功判据对得上；至少一张票无阻塞（frontier 非空） | `ticket-plan` |
   | 5 | 实行 | 代码 + 测试 | 测试先红后绿，且挂在事先约定的接缝上 | `build-ticket` |
   | 6 | 检测 | 双轴报告 + 你本人的验收结论 | 两轴无未决发现项；你本人跑过一遍并留了结论 | `dual-axis-review`（出 bug → `bug-diagnosis`） |
   | 7 | 交付 | 提交钩子 + PR + 交接文档 | 钩子跑过；PR 说清怎么验证；交接文档只给路径 | `session-handoff` |
   | 8 | 开源发布与运营 | LICENSE + README + CI + 社区文件 + 首个 release | 陌生人 30 分钟能跑起来，并知道怎么参与 | `oss-launch` |

5. **抄路由表**——把「你现在处在什么状态」换成技能名。一次只调一个。

   | 你现在处在什么状态 | 调用 |
   |---|---|
   | 「我想做个东西」，一句话还说不清是什么 | `project-brief` |
   | 不知道这活该走几步、能不能省事 | 本技能（判档位） |
   | 手上只有一个空目录，还没 `git init` | `repo-bootstrap` |
   | 仓库能提交了，但不知道 spec 与票据往哪写 | `repo-setup` |
   | 要开工，需求还只在脑子里 | `grill-with-ledger` |
   | 刚谈完一轮，担心决议会丢 | `decision-ledger` |
   | 工程一次会话装不下，要一份能给人看的文档 | `write-spec` |
   | 有 spec 或一堆需求，不知道先做哪块 | `ticket-plan` |
   | 票据图在，要动手做其中一张 | `build-ticket` |
   | 一张票做完了，要交给人审或自查 | `dual-axis-review` |
   | 有个 bug 反复修不好，或者出现性能回退 | `bug-diagnosis` |
   | 上下文快满了、要换会话，或者一票做完要交出去 | `session-handoff` |
   | 代码能跑了，要让别人用、要对外开源 | `oss-launch` |
   | 跑了几轮，想知道这套流程有没有用、该改哪一步 | `flow-tuning` |
   | 同一件事连着两次没收敛 | 停手，回上一层：`ticket-plan` / `grill-with-ledger` / 做一次性原型 |

6. **把三条铁律写成口令**（原样抄进目标仓库 `AGENTS.md`，它是给下一个会话看的）：
   - 一票一会话：**「做完这张票，我开新会话。」** 票据 2 只读票据文件本身，不继承票据 1 的中间讨论与踩坑。
   - 谈完立刻落盘：**「这条定下来了吗？定下来现在就写进台账。」** 谈完与落盘之间不要隔夜，也不要插别的事。
   - 两次不收敛就上移一层：**「连着两次没收敛，停手，回上一层。」** 重切票据 / 补一句需求 / 做原型，而不是「再试一次」。

7. **把权限边界写进同一个 `AGENTS.md`**。代理可以读代码、写代码、跑测试、翻文档；下面这些**不可以**，要你显式批准，最好由你亲手做：
   - 碰密钥、生产环境凭据、发布凭据；
   - 对共享分支 force push、重写历史、删数据；
   - 发版、把仓库转为公开、改许可证或对外承诺；
   - 替你签字：法务判断、隐私声明、对他人的承诺。

   理由一句话：这些动作不可逆或影响别人，而代理的「自信」与「正确」之间没有相关性。

8. **把这一轮的判断写成两行**，留在会话里或 `AGENTS.md` 里：
   `档位：L1 ｜ 当前：第 2 步 ｜ 下一步：grill-with-ledger`
   跳过的步在后面补一句凭什么跳（例如「L1 跳过第 3、4 步：一张票就能做完」）。

## 产出物

- 一行档位判断，含升级判据的对照结果。
- 一行「当前第几步 / 下一个技能」。
- 目标仓库 `AGENTS.md` 里的三样东西：九步索引、三条铁律口令、权限边界清单。
- 可选：把本技能的九步地图剪成一张 `docs/agents/flow.md`，供下一个人接手时读。

## 完成判据

- [ ] 档位（L0 / L1 / L2）判出来了，并写下了一行 `档位：L?`。
- [ ] 升级判据四条逐条对照过，结果写下来了（命中哪一条，或全不命中）。
- [ ] 写下了一行 `当前：第 N 步 ｜ 下一步：<技能名>`，技能名是这十四条里真实存在的一个。
- [ ] 被跳过的步逐条写明了凭什么跳；写「感觉不用」不算。
- [ ] 三条铁律的口令已经在目标仓库的 `AGENTS.md` 里，能指到具体那几行。
- [ ] 权限边界清单在同一个 `AGENTS.md` 里，且当前没有任何越界动作正在跑。
- [ ] 这一轮要交付的判据都是 `- [ ]` 形式，每条能跑一条命令、能指到一个文件，或能回答一个问题。

## 手工兜底

- 完全没装这套技能集：九步照样走。手册附录 C1 的九条判据打印一页贴在显示器边，TL;DR 的九行表就是全部地图（本技能第 4 步的表就是从它抄的）。
- 只有一张便签的时间：写三行——档位、当前步、下一步。其余按需查每个技能自己的「手工兜底」节。
- 判不准档位：**往上取一档**。多走一步的成本，永远低于在第 5 步返工。
- 完全离线、不许开代理：附录 A 的模板 + 每个技能的手工兜底节就是无代理版本，判据一条都不用改。
- 用户不肯判档位、只想直接写代码：L0 的走法也要求「git 卫生 + 密钥边界」两条，这两条谈不下来就先别写代码。

## 下一步

→ 按第 5 步的路由表调用那一个技能；没有 brief 先 `project-brief`，没有仓库先 `repo-bootstrap`，有仓库没配置先 `repo-setup`。

## 反模式

| 反模式 | 为什么错 | 改成 |
|---|---|---|
| 每次都从第 0 步走全九步 | 一天的活被流程吃掉，人会开始绕过流程 | 先判档位，L0 只走 0 → 5 → 6 |
| 跳过第 2 步直接实现 | 需求在实现中途才暴露，返工加倍 | L1 及以上必须拷问，L0 才可跳 |
| 档位判高了不降、判低了不升 | 判据按档位裁剪，档位错了整条判据都错 | 每次会话开头重判一次，降级已给判据 |
| 一次调用多个技能「省事」 | 上下文被多个技能的规则挤占，产出更差 | 一次一个，做完再换 |
| 把「下一步：看着办」写进 AGENTS.md | 下一个会话仍然不知道从哪开工 | 必须写成具体技能名 |
| 让代理替你判许可证、公开仓库、签字 | 不可逆或影响别人，代理的自信与正确无关 | 你亲手做，代理最多整理选项 |
