# 拷问（谈定一件落一件）

> 对应手册第 2 步 ｜ 产出物：`CONTEXT.md` + 决议台账 + `docs/adr/`（可能有 0 条）+ 验收方式 ｜ 完成判据：术语表非空；台账每条决议可验证；该类决策有 ADR（没有就明写「本步无 ADR」）；验收方式可执行

## 何时用 / 何时不用

**用**：需求还只在脑子里；L1 / L2 档开工前；写 spec 之前；拆票之前发现「说不清要什么」时。

**不用**：
- 工程大到一次会话装不下 → 先做决策地图，别在这一步硬谈（→ 调用 `ticket-plan`：多一份 `map.md`、票据多一行 `Type:`；装了外部 `wayfinder` 就用它）。
- 要问的东西在别人脑子里（用户、同事、甲方）→ 做成问卷发出去（见「手工兜底」），不要替对方回答。
- L0（半天内做完、只你自己用、不进主干）→ 可以跳过拷问，直接干活。

**它长什么样**：你不需要憋出一份完美的需求描述。它反过来拷问你：一轮问题 → 等你答 → 下一轮，每个问题附上它的推荐答案，你可以直接说「同意」。

| 谈定了什么 | 落到哪里 | 什么时候写 |
|---|---|---|
| 一个术语——项目里对这事的正式叫法 | `CONTEXT.md` | **当场写入，不攒到最后** |
| 一个决策，同时满足「难逆转 + 脱离上下文会费解 + 真实权衡」 | `docs/adr/` 下的 ADR | 谈定那一轮 |
| 其他所有谈定的东西 | 只在对话里，不落盘 | —— |

**第三行最容易吃亏**：`CONTEXT.md` 只是词汇表，不是规格；ADR 的三道门槛卡得很严，大多数会话一条都不产生。所以谈完必须立刻落盘并进第 3 步，否则谈定的东西跟着上下文一起消失。

**三个已知问题**（按 v1.2.3 的技能正文逐条核对过）：

1. **决议在传递中被压弱——最重要的一条。** `CONTEXT.md` 按设计只是术语表；多数决议不够格写 ADR；第 3 步的 spec 会从对话里重新综合一遍，中间没有任何「每条已定决议都进了用户故事、验收项和实现」的完整性检查。精确结论会被压成弱表述：「标签顺序在重启后必须保持不变」变成「persist sessions」，实现只要满足这句弱表述就算完成。**同一次会话里也会发生，不需要上下文过期。** 这就是台账存在的理由（→ 调用 `decision-ledger`）。
2. **一口气问了一堆问题、没有推荐答案、也没提 `CONTEXT.md`** → 说明依赖没加载成功。直接问它：「你加载了哪几个技能？」
3. **单独安装不工作** → 拷问技能缺依赖时会退化成一场没有产出的普通提问，谈了半天一个字没落盘。

## 输入（开工前必须到手的）

1. 一个已初始化的仓库（第 1 步产物）：git 可用、首次提交在——不然谈定的东西没地方落。
2. 一句话想法，最好已经有 `brief.md`（第 0 步的「不做什么」与「放弃条件」）。
3. 三个落点的位置（默认：仓库根 `CONTEXT.md`、`docs/decisions.md`、`docs/adr/`）。
4. 本次档位判断：L0 可跳过，L1 / L2 必做。

## 动作

1. **先定落点，一次定死。** 术语表、台账、ADR 目录各在哪，写进 `AGENTS.md`，别让下一个会话再猜。
2. **给出口令，让它反过来问你**：一轮 3–5 个问题，每个问题附上它的推荐答案，你答完它再问下一轮。明确写上「不要一次问完」「不要替我决定」。你回「同意」就是采信它的推荐答案。
3. **谈定一件落一件，不攒到最后**（清空会话等于全部作废）：
   - 术语 → `CONTEXT.md` 追加一行：术语 / 一句话定义 / 别叫它。
   - 决议 → 台账追加一行带编号，编号不复用（→ 调用 `decision-ledger`）。
4. **ADR 严格卡三条门槛**：难逆转 + 脱离上下文会费解 + 真实权衡，**三条同时满足**才写 `docs/adr/NNNN-*.md`。一条都不产生是正常的；这时在仓库里明写「本步无 ADR」，而不是让它空着让人猜。
5. **专门问出边界与「不做什么」**：出错时怎么办、空状态长什么样、谁能看谁能改（权限）、哪些明确不做。这四类问题最容易在实现中途才暴露，那时返工加倍。
6. **必须问出验收方式**：每条成功判据都要落到「怎么验证」——一条能跑的命令，或一个具体动作。这句话会一路传到第 3 步的「测试决策」、票据头 `Verify:` 行、第 6 步的验收。**事后补验收，等于没有验收。** 写不出验证方式的判据，当场标成「待定」并给期限。
7. **收官前必问两句**（很便宜，常常挖出真风险和一次沉默的越权假设）：
   - 「还有哪三个问题你没问？」
   - 「这轮有哪些结论是你替我决定的？」——替你做主的，逐条进台账。
8. **收敛检查**：超过若干轮还在问「要不要做」而不是「怎么做」，说明卡的是立项判断，不是需求细节——停下来回第 0 步补成功判据（→ 调用 `project-brief`），别继续问细节。

## 产出物

- `CONTEXT.md`（术语表，非空）。
- 决议台账：`docs/decisions.md` 或 `.scratch/<feature>/ledger.md`（非空，四列，编号不复用）。
- `docs/adr/` 下 0 条或多条 ADR（0 条要有「本步无 ADR」这句话）。
- 写进 `brief.md` 或票据的验收方式（每条判据 → 怎么验证）。
- 模板：`templates/CONTEXT.md`、`templates/ledger.md`、`templates/adr.md`。

## 完成判据

- [ ] `CONTEXT.md` 存在且非空；每条术语能一句话解释，且写了「别叫它」。
- [ ] 台账存在且非空；每行四列齐全（编号 / 类型 / 精确到可验证的决议 / 证据），证据栏非空。
- [ ] 台账编号连续、无复用。
- [ ] 每条决议都能写出一条验证命令或动作；写不出的已标「待定」并带期限。
- [ ] `docs/adr/` 里每一条都同时满足三条门槛；一条都没有时，仓库里有「本步无 ADR」。
- [ ] 每条成功判据都写明了「怎么验证」（一条命令或一个动作）。
- [ ] 已问过「还有哪三个问题你没问？」与「这轮有哪些结论是你替我决定的？」；后者逐条进了台账。
- [ ] 三个落点的位置写进了 `AGENTS.md`。
- [ ] 还在争「要不要做」的问题已回到第 0 步，没有被当成需求细节继续谈。

## 手工兜底

- **没有 grilling / grill-with-docs 这类外部技能**：自己列 20 个问题逐个回答，两类必须覆盖——「边界情况」和「不做什么」。术语照 `templates/CONTEXT.md` 补，决议进台账（`templates/ledger.md`），够格的三条决策用 `templates/adr.md` 写。如果装了拷问类技能就用它来问；没有就按这条手工路径走，判据一样成立。
- **要问的东西在别人脑子里**：做成一份问卷（同一批问题 + 你预设的推荐答案），发出去收回来，再逐条落盘。不要替对方回答。
- **技能静默不落盘**（问了半天什么都没写）：换一个会话，把对话记录粘回去，用第 3 步的三行表逐条手工落盘——落盘不依赖任何技能。
- **你自己就是唯一的人**：把推荐答案当成「假想同事的回答」，逐条问自己「他会不会反对」，反对的地方就是真问题。

## 下一步

→ 一次会话能做完：直接调用 `build-ticket`（用 `templates/ticket.md` 现写一张票，不走票据图）；多张票或跨会话：先 `write-spec`，再 `ticket-plan`。

## 反模式

| 反模式 | 为什么错 | 改成 |
|---|---|---|
| 一口气抛出 20 个问题等你逐个答 | 你会挑简单的答，最难的问题正好消失 | 一轮 3–5 个，每个附推荐答案 |
| 让代理替你决定然后直接往下走 | 项目里出现了你从没同意过的约束 | 收官必问「哪些结论是你替我决定的」，逐条进台账 |
| 谈完不落盘，指望下一个会话记得 | 没写下来的共识等于没发生 | 谈定一件落一件，当场写 |
| 把 `CONTEXT.md` 当规格用 | 它只是词汇表，实现细节它兜不住 | 决议进台账，够格的写 ADR，其余当场进第 3 步 |
| 顺手把每条决策都写成 ADR | 门槛一松，ADR 就没有信息量，没人再读 | 三条门槛同时满足才写；一条没有就明写「本步无 ADR」 |
| 跳过这一步直接实现 | 需求在实现中途才暴露，返工加倍 | L1 / L2 先拷问；两次不收敛就上移一层 |
