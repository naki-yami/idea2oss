# 手工两轴评审清单（code-review 的替代）

> 第 6 步 · 技术验收 ｜ 判据：两轴都无未决发现项；有未决项的，每项必须写"接受的风险 + 谁接受"
> 用法：先跑标准轴，再逐条对规格轴；发现项当场开票，不要标"以后再说"

## 标准轴（代码是否符合**这个仓库自己写下来的**规范）

- [ ] 命名与目录结构符合仓库已有的约定？
- [ ] 有没有把配置、密钥、魔法数写死在代码里？
- [ ] 错误路径处理了吗，还是只处理了顺利路径？
- [ ] 有没有重复实现本该复用的模块？
- [ ] 测试是否通过公共接口断言行为，而不是实现细节？
- [ ] 有没有留下为了过关而凑的 TODO、注释掉的代码、临时开关？

## 规格轴（代码是否忠实实现了文档的每一条）

- [ ] spec 的每条成功判据，能不能在代码里指出对应实现？
- [ ] 「范围之外」里被拒绝的东西，有没有偷偷做进来？
- [ ] 票据头 `Verify:` 那条命令跑通了吗？
- [ ] 台账里每条决议，能不能在实现与验证里找到证据？（找不到 → 开票或写进「范围之外」，不要放着）
- [ ] 有没有 spec 没写、代码里却出现的新行为？（有 → 要么补文档，要么删）
- [ ] 契约变化（接口签名、数据结构、错误码）记录了吗？

## 结论（必须写）

- 标准轴未决发现项：0 ／ 数量 + 每项的"接受的风险 + 谁接受"
- 规格轴未决发现项：0 ／ 同上
