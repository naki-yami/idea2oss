# 接手者 30 分钟路径

<!-- 第 8 步判据「陌生人 30 分钟测试」的操作版：别人只读 README，能在干净环境里装起来、
     跑通一次、并知道要参与该改哪个文件。每一步卡住，就是结构缺了那一件。 -->

| 分钟 | 做什么 | 读哪个文件 |
|---|---|---|
| 0–3 | 知道这是什么、给谁用 | README 前三段 |
| 3–6 | 跑通一次，看到预期输出 | README 的 30 秒上手 |
| 6–10 | 学会项目黑话 | CONTEXT.md |
| 10–14 | 知道模块边界与公共接缝 | docs/architecture.md |
| 14–18 | 知道"为什么不是另一种做法" | docs/adr/ 最新三条 + docs/decisions.md |
| 18–22 | 知道下一步该干什么 | .scratch/<feature>/issues/ 或 Issues（看 frontier） |
| 22–26 | 知道怎么提改动、多久有人回 | CONTRIBUTING.md + SECURITY.md |
| 26–30 | 改一行 → 提 PR → 看 CI 跑 | CHANGELOG.md + CI 日志 |

30 分钟后你应该能答：它是什么 / 怎么跑 / 下一步该做什么 / 怎么把改动提进来。
答不上来 —— 请在这里开一个 issue，说明卡在哪一步。
