# idea2oss 技能集 · 编写契约（所有技能必须遵守）

> 这是给"写技能的人/代理"看的规范，不是给人读的文档。写完删掉本文件的引用即可。
> 基准样板：`skills/decision-ledger/SKILL.md`（先读它，再动笔）

---

## 一、身份与来源

- 技能集名：**idea2oss**（从想法到开源），对应《AI 结对开发流程手册 V3》的九步。
- 每个技能＝手册里的一步或一条横向纪律。**手册是唯一事实来源**，写技能时以 `D:\dsh\.scratch\v3-read\v3.md`（手册全文）为准。
- 目标：可独立分享。**不得假设任何外部技能存在**——凡提到外部技能（grilling / tdd / code-review / research / handoff …），一律写成"如果有 X，用它；没有就按下面的手工路径走"。

## 二、文件与命名

```
skills/<name>/SKILL.md          ← 必须，唯一入口
skills/<name>/references/*.md   ← 可选，深度内容（长表、清单、大段模板说明）
```

- `<name>` 用英文 kebab-case，**必须与 frontmatter 的 `name` 完全一致**，也与目录名一致。
- 一个技能只做一件事。名字是动词短语或清晰名词：`project-brief`、`ticket-plan`、`dual-axis-review`。
- 不要在技能之间复制大段内容：正文只留判据，重复的长内容放 `templates/` 或自己的 `references/`，用路径引用。

## 三、frontmatter（三个字段，缺一不可）

```yaml
---
name: decision-ledger
description: 维护决议台账：谈定一条决议就追加一行带编号的记录，让 spec、票据、验收都能回指，从而发现"决议在传递中被压弱"。当用户要"记下这个决定""为什么当初这么定""决议追溯率"或准备写 spec/拆票时使用。keywords: decision ledger, decision log, ADR, traceability, spec drift, requirements loss
whenToUse: 第 2 步谈定决议后、写 spec 前、拆票时、验收前。
---
```

- `description`：**中文，两到三句**。第一句写"做什么"，第二句写"什么时候用"（这部分决定能不能被自动触发），最后追加 `keywords:` 一行英文关键词（提高英文环境命中率）。
- `whenToUse`：一行，列触发时点。
- 总长度控制在 260 字以内。

## 四、正文骨架（八节，顺序固定，标题照抄中文）

```markdown
# <中文标题>

> 对应手册第 N 步 ｜ 产出物：<文件/字段> ｜ 完成判据：<一句话>

## 何时用 / 何时不用
## 输入（开工前必须到手的）
## 动作（编号步骤，每步可执行、可验收）
## 产出物
## 完成判据
## 手工兜底（不依赖任何技能/工具也能走完）
## 下一步
## 反模式
```

- **动作**节：每步以动词开头，写清"做到什么程度算这一步完成"。
- **完成判据**节：逐条 `- [ ]`，每条必须**可检查**（能跑一条命令、能指到一个文件、能回答一个问题）。写不出可检查的判据，就不是判据。
- **手工兜底**节：这是本技能集的卖点，不能省。写"技能/工具/环境不可用时，人照着做的最小替代路径"。做不到就写"无替代，必须先解决 X"。
- **下一步**节：一行，写 `→ 调用 \`<skill-name>\``（没有下一个技能就写"回第 0 步"）。
- **反模式**节：3–6 条，写"看起来省事、实际加倍偿还"的做法。

## 五、引用规则

- 引用技能：`` → 调用 `ticket-plan` ``（反引号包住技能名，必须是本集内真实存在的目录名）。
- 引用模板：`templates/spec.md`（相对仓库根）。
- 引用手册：写"手册第 N 步 / 第 N 章"，不要写页码。

## 六、文风

- 第二人称、指令式、短句。**不写空话和铺垫**，不写"众所周知"。
- 中英混排加半角空格；标点用全角；判据用 `- [ ]`。
- 允许直接给"话术"和"口令"（例如拒收时说哪一句），这是本手册的风格。
- 用表格搬运对照关系（类型/档位/选项），用列表写动作。

## 七、长度

- SKILL.md：**80–220 行**。少于 80 行说明判据不细，多于 220 行请拆进 `references/`。
- 不写"参考手册全文"这类空引用；要抄就把关键判据抄准。

## 八、交付前自检（写完逐条过）

1. `name` == 目录名 == frontmatter 里的名字。
2. 八节都在，标题没改名。
3. 完成判据全部可检查。
4. 手工兜底节非空。
5. 正文里出现的每个 `` `技能名` `` 都是本集真实存在的技能（或明确标注"外部技能，如已安装"）。
6. 没有假设用户装过任何技能集。
