## 要什么

体检器多一项判据：**活文档里没有与事实相反的断言**。文档说「远端还没接」「`git tag` 为空」「它检查 28 项」，而仓库实际不是——这一项就红，并点到「文件:行 + 实际值」。

为什么要有它：票据 04 抓到的 6 处问题全是「文件与事实对不上」，靠人肉发现；修完当次之后，同类断言没有留下任何防线——下一次照样会飘。**判据不落成命令，就只是纸面话术。**

## 怎么算做完

- [ ] `check_project.py` 有「活文档里没有与事实相反的断言」一项，属 L2 强制项
- [ ] 核对的事实覆盖：远端 / tag / 用例数 / 工具入口数 / 判据条数 / 台账编号区间与条数 / 自报分数
- [ ] 报错文本点到「文件:行 + 实际值」，不然看不懂该改哪句
- [ ] 取不到事实的项**跳过并打印**，不误报也不假装查过（浅克隆里 `git tag` 空着 ≠ 没有 tag）
- [ ] 快照不参与核对：`CHANGELOG.md`、票据、ADR、`docs/release-checklist.md` 记的是某个时点发生了什么
- [ ] 本仓库跑这一项为 `[x]`（它上线时当场抓出的 7 处已全部改成事实）
- [ ] 回归测试钉住 7 条：对不上要红 / 对得上要绿 / 快照不查 / 工具入口数对不上要红 / 浅克隆跳过 / 其余项没全过时不比对自报分数 / 本仓库自己全过

## 不做什么

- 不查「N 个测试」这类局部计数（`docs/architecture.md` 里「S6 一进仓库就带了 5 个测试」不是总数），泛化就是假阳性
- 不回头改快照——那是伪造证据
- 不替文档做语义判断：只认能机械核对的那几类断言
