## 要什么

**已完成。** 验证指针：`python tools/check_project.py --dir . --level L2 --quiet`，实跑输出见文件底部的 Comments 段。

你不再需要读一遍文档才能判断一个项目够不够「可接手」：跑一条命令，它逐项给出证据，告诉你缺什么、先补哪三件；有强制项没过就退出码 1。

这条命令有三个调用方：CI 的 PR 门禁（03 接进去）、每张票的 `Verify:`、刚接手这个仓库的人。凡是机器判断得了的判据，都必须落成这条命令里的一项。

## 怎么算做完

- [ ] `python tools/check_project.py --dir . --level L2 --quiet` 在本仓库跑得起来，逐项打印通过 / 缺失 / 警告 / 不适用，末尾给完整度与「最该先补的三件」
- [ ] 退出码语义成立：有强制项未过时退 1，全过时退 0 —— 本票落盘时是 15/26、退 1，缺件补齐后是 28/28、退 0，两条分支都实跑过（证据在文件底部的 Comments 段）
- [ ] 每个缺失项带一条「→ 先补什么」的修复建议，而不是只报一个错
- [ ] 三个开关各自成立：`--level` 决定哪些项是强制项（空项目跑 L0 只强制 4 项）、`--quiet` 只打未过项、`--json` 给 CI 读
- [ ] 在一个空目录上跑不崩，给出的是缺件清单而不是一个分数

## 不做什么

- 不查质量：测试是否挂在接缝上、文档是不是你要的，机器判不了，留给第 6 步的 `Accept:`
- 不做自动修复：不替你写 README、不替你建 `tests/`
- 不并入 `scaffold_project.py`（外部工具，本期不并入，避免两处维护同一批模板）
