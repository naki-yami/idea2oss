## 1. 问题陈述

`idea2oss` 的技能已经能用了，但仓库本身不满足它自己定的「完整项目」标准：用 `tools/check_project.py` 量自己只有 **50%**——没有测试、没有 CI、没有社区文件、没有台账与票据、没有接手路径。

后果具体而不抽象：陌生人 clone 下来不知道先读什么（没有 `docs/onboarding.md`）；改一个技能没有任何东西会拦住他（没有 CI）；想知道「为什么是 14 个而不是 1 个」要翻 git 历史（没有 ADR）；发布时没有 CHANGELOG 与 tag（没有版本纪律）。**一个把「可接手」写进判据的项目，自己不可接手。**

他们现在怎么绕过：靠作者本人在场口头解释——这正是本项目要消灭的依赖。

## 2. 解决方案

用本集自己的九步流程，把 `idea2oss` 从「能用的技能目录」补成**可接手、可发布、可验证的完整项目**：立项与台账落盘、接缝写下来、票据成图、测试挂在接缝上、CI 在 PR 上跑并挡合并、社区文件齐全，最终由 `check_project.py` 给出可复现的合规分数。

不写实现细节。

## 3. 用户故事

**首次使用**：作为第一次接触这套技能的人，我 clone 后在 5 分钟内知道「这是什么、给谁用、怎么装」，并在 30 分钟内走完一次 L0 全程，以便判断它值不值得我下次再用。

**重复使用**：作为已经用过一次的人，我想直接跳到某一环（比如只想要决议台账），不必重读九步，以便把它嵌进我现有的工作流。

**出错**：作为改坏了一个技能的人，我提 PR 时 CI 立刻告诉我哪一节缺了、哪个交叉引用指错了，以便我在五分钟内改对，而不是等维护者回信。

**边界**：作为只想要一部分的人，我只拷贝 `skills/ticket-plan/` 一个目录，它必须能独立工作（不引用任何本集之外的东西）。

**空状态**：作为一个还没开始的项目，我跑 `check_project.py` 时应该拿到「缺什么 + 先补哪三件」，而不是一个分数。

**权限**：作为维护者，我让代理改技能正文时，它不得替我发版、不得改许可证、不得动 git 历史。

## 4. 实现决策

- 技能保持并列式、可独立拿走，不得引入任何跨技能硬依赖 `[D-01]`
- 八节骨架固定，作为机器可校验的契约（`S1`）`[D-02]`
- 每条完成判据可检查，每份技能至少 4 条 `- [ ]` `[D-03]`
- 台账只放 `docs/decisions.md` 一处，编号不复用 `[D-04]`
- 结构判据落成可执行体检器（`S2`），失败退出码 1 `[D-05]`
- `tools/` 零第三方依赖（`S3`）`[D-06]`
- 正文中文、description 带英文 keywords `[D-07]`
- `templates/` 是导出物，生成器是事实来源 `[D-08]`
- 交接文档不进仓库 `[D-09]`
- 版本与 CHANGELOG 纪律 `[D-10]`
- 依赖许可检查进 CI `[D-12]`
- （`D-11` 英文版正文为待定项，本期不做，期限 v0.2.0）

**接缝清单**（结构见 `docs/architecture.md`）：

| 接缝 | 通过它的是什么 | 谁调用它 |
|---|---|---|
| S1 `validate_skills.py` | 技能契约 + 退出码 | CI、贡献者 |
| S2 `check_project.py --json` | 结构判据结果 + 退出码 | CI、票据 Verify、接手者 |
| S3 `install.py` | 安装行为与 `--list` 输出 | 使用者 |
| S4 `SKILL.md` frontmatter | 对外承诺的三个字段 | 运行时、S1 |
| S5 `templates/*` | 结构约定 | 技能正文（目前单一调用方，暂不测） |

架构性决策另外落 ADR：0001 并列式技能集、0002 中文正文加英文关键词、0003 判据做成体检器。

## 5. 测试决策

- 测试只挂在 `S1` / `S2` / `S3` 三个真接缝上，断言**行为**（退出码、输出字段），不断言实现细节 `[D-03]`
- `S1`：合法技能集 → 退出码 0；缺一节 / `name` 与目录不符 / 引用不存在的技能 → 退出码 1 且错误文本含对应关键词
- `S2`：完整骨架 → 高通过数；空目录 → 缺 `README` 与 `.gitignore`；`--level L0` 只强制 4 项 `[D-05]`
- `S3`：`--list` 在未安装目录上返回 0；`--dry-run` 不写盘 `[D-06]`
- 每条成功判据的验证方式：见票据头 `Verify:`——`python -m unittest discover -s tests` 与 `python tools/check_project.py --dir . --quiet`

## 6. 范围之外

- **不做英文版技能正文**：`D-11` 是待定项，期限 v0.2.0；本期只保证 `keywords` 覆盖英文检索词。
- **不做 Web 界面 / 运行时**：本集是技能与工具，不是应用。
- **不做项目骨架生成器**：`scaffold_project.py` 是外部工具，本期不并入（避免两处维护同一批模板）。
- **不做自动改技能的工具**：改技能的入口是编辑器，校验器只负责说「不通过」。
- **不追求 100% 的体检分数**：有几项（`license` 元数据、`env.example`）取决于项目类型，硬凑会引入无意义的文件——本项目按需满足，缺项在 README 的「限制」里写明。
